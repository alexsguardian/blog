If you answered yes to the question in the title, you are probably experiencing the inability to cast media properly to devices located on a IoT VLAN. Well you’re in luck! An awesome member of the Ubiquiti community <a href="https://github.com/scyto/multicast-relay">created a docker container</a> for the <a href="https://github.com/alsmith/multicast-relay">multicast-relay service</a> that can be deployed on the UDM-P.

<Aside type="note">
  This mostly fixes the mDNS relay issues that the UDM-P experiences. However, apparently with firmware 1.8+ it’s supposedly being fixed and this container is not really required. But it’s Ubiquiti so no idea how long until they actually fix it.
</Aside>

Setting up the container is rather easy. However you need to setup SSH access to your UDM-P. Click <a href="https://help.ui.com/hc/en-us/articles/360049612874-UniFi-UDM-How-to-Login-to-the-Dream-Machine-using-SSH#:~:text=Frequently%20Asked%20Questions%20%28FAQ%29%20%20%20Device%20,of%20Ubiquiti%20SSO%20account%20used%20to%20...%20">here</a> to see Ubiquiti’s docs on enabling SSH on your device.

## Deploying the Container

Once you have SSH enabled log into your UDM-P via a SSH enabled console. I use the Windows Terminal app with PowerShell 7 and the Windows OpenSSH client.

```shell showLineNumbers=false
ssh root@ur.udm.ip.here
```

Once you accept the connection you will get access to the UDM-P’s CLI. From here we can run the following command to get the info we need for the container.

<Image src={udmpSSH} alt="UDM-P SSH Session" class="rounded-lg shadow-lg flex mx-auto" />
<ImgDesc>UDM-P SSH Session welcome screen</ImgDesc>

```shell showLineNumbers=false
ifconfig
```

This command will return all of your network interfaces.

*You will want to make note of the two bridge interfaces of the networks you want mDNS to route between via the container. For me it’s br0 and br2.*

Once we have the interfaces, we can deploy the container. Since the UDM-P uses Podman rather than Docker, we need to change up the command a bit to make it work. See <a href="https://medium.com/technopanti/docker-vs-podman-c03359fabf77">here</a> for Docker vs Podman.

```shell showLineNumbers=false
podman run -rm -it --network=host -e INTERFACES="br0 br2" --restart=always --name ssdp-relay scyto/multicast-relay
```

Once the command is executed, an ID is returned for the container verifying that it was deployed. To actually verify it is running, we can run:

```shell showLineNumbers=false
podman ps
```

<Image src={udmpPodman} alt="UDM-P Podman Container" class="rounded-lg shadow-lg flex mx-auto" />
<ImgDesc>fervent_grothendieck is the mDNS relay container.</ImgDesc>

To see the container logs we can run:

```shell showLineNumbers=false
podman logs -f container_name
```

If the container is properly running you will see messages in the log that look similar to this image:

<Image src={multicastRelay} alt="UDM-P Podman Container Logs" class="rounded-lg shadow-lg flex mx-auto" />

To exit the log, hit CTRL+C.

Now that the mDNS relay service is running, try and connect to your device from your main LAN. You should now be able to see your devices. Just note that if your router’s firewall is blocking established/related connections between your main LAN and IoT VLAN you won’t be able to connect.
